Project Overview

PowerFit Gym Management System is a web-based application that digitises and automates the complete operations of a fitness gym. The system replaces traditional paper-based record keeping with a centralized, secure, and interactive digital platform accessible through any web browser.

The application serves two primary user roles — Administrator and Member — each with a dedicated, session-protected interface. Admins oversee all gym operations from an analytics-driven dashboard, while members independently manage their profile, attendance, BMI, and workout plans.

🏋️

Gym Name

PowerFit Gym – a modern fitness centre focused on health, strength, and consistency.

🌐

Deployment

Apache Tomcat 11 on localhost; accessible via any standard web browser on the local network.

👥

User Roles

Administrator and registered Members. Each role has distinct privileges and interfaces.

🔒

Security

AES-128 encrypted passwords, PreparedStatement queries, and session-based authentication.

2

Objectives

  • To provide a centralised platform for managing gym members, membership plans, and records.
  • To enable secure registration and login for members with AES-128 encrypted credentials.
  • To allow members to self-manage their profiles, track attendance, and calculate BMI without admin help.
  • To give administrators a real-time analytics dashboard showing total, active, and expired membership counts.
  • To automate membership expiry tracking based on the selected plan duration at registration time.
  • To deliver personalised workout plans based on member BMI and fitness goals.
  • To implement a forgot password system that generates a new password and emails it via SMTP.
  • To build a fully responsive, visually polished UI that is intuitive for non-technical users.

Use Case Description

UC-01: Member Registration

ActorGuest User
TriggerUser clicks "Join Now" or navigates to register.jsp
PreconditionUser is not logged in; email is not already registered
Main FlowFill form → JS validate → Server check email uniqueness → AES encrypt password → Compute expiry date → INSERT into members → Redirect to login
Alternate FlowIf email exists → show "Email already registered" error
Validation RulesAge 16–70; Indian mobile starting 6-9; strong password (upper+lower+digit+special); height 100–250 cm; weight 20–250 kg

UC-02: Member Login

ActorRegistered Member
Main FlowEnter email + password → AES encrypt input → SELECT from members → Match found → Set session (member_id, name) → Redirect to dashboard
Alternate FlowNo match → show "Invalid email or password"

UC-03: Mark Attendance

ActorLogged-in Member
Main FlowClick button → POST request → INSERT into attendance (date + time + 'Present') → Show success and updated log
Alternate FlowUNIQUE constraint violation → show "already marked today" warning

UC-04: Forgot Password

ActorRegistered Member (not logged in)
Main FlowEnter email → Verify in DB → Generate 8-char random password → AES encrypt → UPDATE members → Send email via SMTP → Show success
Alternate Flow AEmail not found → "No account registered" error
Alternate Flow BSMTP failure → Display new password on screen with warning

UC-05: Admin – Delete Member

ActorAdmin
Main FlowClick Delete → JS confirm dialog → GET with member_id → DELETE FROM members → Show success
Alternate FlowCancel confirm → No action taken

Security Features

🔐

AES-128 Password Encryption

All passwords encrypted using AES/ECB/PKCS5 with a 16-byte key before storage. Passwords are never stored in plain text.

🧩

SQL Injection Prevention

All DB operations use PreparedStatement with parameter binding — no raw string concatenation in queries.

🔑

Session-Based Auth

Server-side sessions store member_id or admin_user. Every protected page validates the session before serving content.

🚫

Unauthorized Access Block

Direct URL access to protected pages without a valid session results in immediate redirect to the login page.

✅

Dual-Side Validation

All forms validated on both client (JavaScript) and server (Java) sides to prevent malformed or malicious input.

📧

Gmail App Password (SMTP)

Email uses a revocable Google App Password — completely separate from the main account password.

Installation & Setup Guide

Step 1 – Database Setup

-- Run in MySQL Workbench or command line
CREATE DATABASE gym_management;
USE gym_management;

CREATE TABLE membership_plan (
    plan_id INT AUTO_INCREMENT PRIMARY KEY,
    plan_name VARCHAR(50), duration_months INT, fees DOUBLE
);
INSERT INTO membership_plan VALUES(NULL,'Basic',1,999),(NULL,'Standard',3,1499),(NULL,'Premium',12,2499);

CREATE TABLE members (
    member_id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100), gender VARCHAR(10), dob DATE, age INT,
    mobile VARCHAR(15), email VARCHAR(100) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL, address TEXT,
    height DOUBLE, weight DOUBLE, plan_id INT,
    join_date DATE, expiry_date DATE
);

CREATE TABLE admin (username VARCHAR(50) PRIMARY KEY, password VARCHAR(100));
INSERT INTO admin VALUES('admin','admin123');

Step 2 – Update DB Credentials in dbcon.java

con = DriverManager.getConnection(
    "jdbc:mysql://localhost:3306/gym_management?useSSL=false&allowPublicKeyRetrieval=true",
    "root",      // ← Your MySQL username
    "Root@123"   // ← Your MySQL password
);

Step 3 – Configure Gmail in Emailclass.java

private static final String SENDER_EMAIL = "your_email@gmail.com";
private static final String SENDER_PASSWORD = "xxxx xxxx xxxx xxxx"; // Gmail App Password
How to get Gmail App Password: Google Account → Security → 2-Step Verification → App Passwords → Generate for "Mail"

Step 4 – Build & Deploy on Tomcat

  1. Open project in NetBeans → Clean and Build
  2. Create context file: apache-tomcat/conf/Catalina/localhost/GymManagementSystem.xml
  3. Content: <Context docBase="C:\...\GymManagementSystem\build\web" path="/GymManagementSystem"/>
  4. Start Tomcat → Open: http://localhost:8080/GymManagementSystem/

Conclusion
